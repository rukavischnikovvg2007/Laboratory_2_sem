## Схема данных (три слоя)

### 1. RAW слой (сырые данные)
- **Назначение:** исходный ответ API без изменений
- **Формат:** JSON
- **Путь:** `data/raw/variant_10/`
- **Особенности:** 
  - Содержит метаданные и данные в одном списке
  - Вложенные структуры (country, indicator)
  - Не пригоден для прямого анализа

### 2. NORMALIZED слой (нормализованные данные)
- **Назначение:** табличный слой после разворачивания JSON
- **Формат:** CSV
- **Путь:** `data/normalized/variant_10/`
- **Структура:**
  - year (int) - год наблюдения
  - value (float) - значение ВВП
  - country_iso3 (str) - код страны
  - country_name (str) - название страны
  - indicator_code (str) - код индикатора
  - indicator_name (str) - название индикатора
- **Зерно:** одна строка = одно значение показателя для одной страны за один год

### 3. MART слой (витрина данных)
- **Назначение:** подготовленная аналитическая таблица
- **Формат:** CSV
- **Путь:** `data/mart/variant_10/`
- **Витрины:**
  
  **Годовая витрина (mart_yearly_*.csv)**
  - Все колонки из normalized
  - Обогащенные данные из справочника (region, income_group, currency, capital)
  - Временные признаки (date, decade)
  
  **Декадная витрина (mart_decade_*.csv)**
  - Агрегация по десятилетиям
  - Метрики: средний, мин, макс ВВП за десятилетие
  
  **KPI сводка (mart_kpi_*.csv)**
  - Ключевые показатели в одной таблице

### Зачем нужны три слоя

| Слой | Зачем | Кто использует |
|------|-------|----------------|
| RAW | Сохранить исходные данные для пересчета | Только скрипты загрузки |
| NORMALIZED | Иметь чистые данные для разных анализов | Аналитики, разные задачи |
| MART | Быстрый ответ на конкретные вопросы | Дашборды, отчеты, презентации |

**Почему нельзя всё в одном файле:**
1. RAW нельзя менять - это единственный источник истины
2. NORMALIZED переиспользуется для разных витрин
3. MART оптимизирован под конкретные вопросы
4. Разделение упрощает отладку и обновление


## Инкрементальность и идемпотентность (Неделя 6)

### 1. Режим full (полная загрузка)

**Что делает:**
- Полностью пересоздает таблицу в базе данных
- Удаляет старую таблицу (`DROP TABLE IF EXISTS`)
- Загружает все данные заново

**Команда запуска:**

`python -m src.pipeline --config configs/variant_10.yml --mode full`

**Когда использовать:**
- Первый запуск пайплайна
- Когда нужно полностью обновить все данные
- При исправлении ошибок в данных
- Идемпотентность: повторный запуск в режиме full дает одинаковый результат (таблица всегда содержит актуальные данные).

### 2. Режим incremental (инкрементальная загрузка)
**Что делает:**
- Читает текущий watermark (максимальный год в базе)
- Загружает из mart-файла только годы больше watermark
- Добавляет новые строки к существующим

**Команда запуска:**
`python -m src.pipeline --config configs/variant_10.yml --mode incremental`

**Когда использовать:**
- При регулярном обновлении данных (например, раз в день/неделю)
- Когда нужно добавить только новые наблюдения
- Идемпотентность: повторный запуск в режиме incremental не создает дубликатов, так как проверяется, что год больше watermark.

### 3. State (состояние пайплайна)
- Где хранится: data/state.json

**Структура файла:**
`
{
"variant_id": "variant_10",
"source_type": "world_bank",
"last_successful_run": "2026-04-06T19:44:06.123456",
"last_watermark": 2025,
"mode": "full"
}
`

**Поля:**

| Поле | Описание |
|------|----------|
| `variant_id` | Идентификатор варианта |
| `source_type` | Тип источника данных |
| `last_successful_run` | Время последнего успешного запуска |
| `last_watermark` | Последний обработанный год |
| `mode` | Режим последнего запуска |

### 4. Business key (бизнес-ключ)
**Что это:** Уникальный идентификатор одной записи в витрине.

**Состав business key:**
- year — год наблюдения
- country_iso3 — код страны (DE)
- indicator_code — код индикатора (NY.GDP.PCAP.CD)

**Почему именно этот ключ:**
- Одна строка в витрине = одно значение ВВП для Германии за один год. Комбинация (год + страна + индикатор) гарантирует уникальность.

**Как используется:**
- Для удаления дубликатов в transform.py
- Для проверки уникальности в SQL-проверках

### 5. Watermark
**Что это:** Метка, до какого момента данные уже обработаны.
- В моем проекте: last_watermark = максимальный год, загруженный в базу данных.

**Как обновляется:**
- После успешного завершения стадии LOAD
- Читается максимальный год из свежего mart-файла
- Сохраняется в data/state.json

**Почему обновляется только после LOAD:**
- Гарантия, что watermark соответствует данным, которые действительно сохранены в базе. Если какая-то стадия упадет, watermark не обновится.

### 6. Структура ETL пайплайна
| Стадия | Файл | Что делает |
|--------|------|-------------|
| Extract | `src/extract.py` | Загружает данные из World Bank API в `data/raw/` |
| Transform | `src/transform.py` | Преобразует raw → normalized → mart |
| Load | `src/load.py` | Загружает mart в базу данных SQLite |

### 7. Запуск пайплайна
**Единая команда:**
`python -m src.pipeline --config configs/variant_10.yml --mode full`
**Альтернативный запуск через bat-файл (опционально):**
`scripts/pipeline.bat`

### 8. Идемпотентность (гарантии)
| Режим | Что гарантирует |
|-------|-----------------|
| Full | Повторный запуск полностью перезаписывает таблицу. Результат одинаковый. |
| Incremental | Повторный запуск не создает дубликатов. Новые данные добавляются только один раз. |

**Как достигается:**
- В full режиме: DROP TABLE IF EXISTS перед загрузкой
- В incremental режиме: проверка year > watermark перед добавлением
- Дедупликация в transform.py по business key

### 9. Пример работы
**Первый запуск (full):**
- Watermark: None → загружены все годы (1976-2025) → Watermark: 2025
**Второй запуск (incremental):**
- Watermark: 2025 → загружены только годы > 2025 → новых данных нет
**Третий запуск (full):**
- Watermark: 2025 → таблица удалена → загружены все годы заново → Watermark: 2025
