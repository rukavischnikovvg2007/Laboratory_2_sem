# Laboratory_2_sem

Описание моего первого проекта по анализу данных.

## Как запустить проект (Windows)

1.  Убедитесь, что у вас установлена Anaconda.
2.  Откройте командную строку (cmd) или PowerShell.
3.  Перейдите в папку с проектом. Например:
    `cd C:\Users\ИМЯ_ПОЛЬЗОВАТЕЛЯ\Desktop\my_data_project`
4.  Запустите главный установочный скрипт одной командой:
    `scripts\setup_env.bat`
5.  Скрипт сам создаст окружение, установит библиотеки и проверит работу.

## Smoke test

После выполнения скрипта вы увидите сообщение `[ok]` или `[ERROR]`. Если всё хорошо, значит проект готов к работе.

## Запуск Extract (загрузка данных)

### 1. Подготовка
Убедитесь, что у вас есть:
- Файл `configs/variant_10.yml`
- Установленные библиотеки: `requests`, `pyyaml` (они уже в `requirements.txt`)

Если библиотеки не установлены:

`pip install -r requirements.txt`

### 2. Запуск скрипта
Откройте командную строку (cmd), перейдите в корневую папку проекта и выполните:

`cd C:\Users\ИМЯ_ПОЛЬЗОВАТЕЛЯ\Desktop\Laboratory_2_sem-main`
`python src/extract.py`

#### 🔹 Если используется Anaconda
1. Откройте **Anaconda Prompt** (Пуск → поиск → Anaconda Prompt)
2. Перейдите в папку проекта:

`cd C:\Users\ИМЯ_ПОЛЬЗОВАТЕЛЯ\Desktop\Laboratory_2_sem-main`

3. Запустите скрипт:

`python src/extract.py`

### 3. Результат
После успешного запуска в папке `data/raw/variant_10/` появится новый файл с именем:

`YYYY-MM-DD_HH-MM-SS.json`
(где `YYYY-MM-DD` — дата, `HH-MM-SS` — время запуска)

### 5. Возможные ошибки

- **`No such file or directory`** — вы не в корне проекта. Нужно перейти в папку `Laboratory_2_sem-main`
- **Ошибки импорта** — не установлены библиотеки. Выполните `pip install -r requirements.txt`
- **Ошибка запроса** — проверьте интернет или временно недоступен `API World Bank`
- **`"pip" не является внутренней или внешней командой`**  
  Решение: используйте **Anaconda Prompt** вместо обычной командной строки
- **Команда `python` зависает или ничего не происходит**  
  Решение: используйте **Anaconda Prompt** или установите Python с официального сайта

### 6. Диагностика (broken_requests.py)
Для проверки работы с HTTP-запросами можно использовать скрипт:

`python broken_requests.py`

Он тестирует разные ситуации: таймауты, ошибки HTTP, не-JSON ответы.
